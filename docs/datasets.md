# Datasets

Every dataset in the repository is either **synthetic** (generated by the project) or a small **public vocabulary** taken from organisational web pages. No real personal data is committed, and none is needed to run, test or evaluate the system.

| Dataset | Location | Size | Kind | Used by |
|---|---|---|---|---|
| Synthetic mentors and mentees | `ml-service/data/synthetic/` | 160 mentors, 300 mentees (about 2.5 MB with hidden labels) | Generated | Recommender evaluation; API seed data |
| Simulated relevance labels | `ml-service/data/synthetic/hidden/` | Every mentee–mentor pair, graded 0/1/2 | Generated | Evaluation only (never seen by the recommender) |
| Aviation mentoring taxonomy and glossary | `ml-service/data/taxonomy/` | 8 specialisations, 57 topics; glossary of term variants | Authored | Matching, profile validation, client pickers |
| Kenya Airways public vocabulary | `ml-service/data/kq_public/` | Fleet types, approvals, service areas, 20 Pride Centre programmes, with page snapshots | Public web pages | Realistic synthetic profiles; programme list |
| Rating kit | `ml-service/ratings/` | Blind rating sheet, pool key, guide, demo ratings | Generated | Expert evaluation study (#30) |
| Sample content | `server/src/seed/sampleContent.js` | 6 articles, 4 events, 3 updates | Authored, labelled "Sample" | Development database |

## Synthetic members

`python scripts/generate_synthetic_data.py` (seed 42) draws hidden ("latent") attributes for each person, such as true domain, expertise level per topic and years of service, and then writes observable profiles from them with realistic noise: under-tagged needs, over-claimed topics, missing fields, unavailable or full mentors, missing consent. Relevance labels come only from the hidden attributes, through a formula fixed before any system was evaluated. Details and formulas: `ml-service/data/synthetic/README.md`.

**Limits.** Nobody in these files exists, and the label formula is an assumption, not a validated model of good mentorship. Results on this data show that the pipeline works and how methods compare under those assumptions, not that matches suit real people. Text comes from a finite phrase bank, which makes text matching easier than in real life; `scripts/run_sensitivity.py` tests a vocabulary-mismatch scenario.

In the web app the same people appear with short display names (for example "Wanjiru C."), sample emails `<id>@sample.daraja.test`, and a "Sample" label.

## Kenya Airways public vocabulary

`scripts/fetch_kq_public_data.py` collected public, organisational pages only. It respects `robots.txt` (fetched with the crawler's own User-Agent), waits two seconds between requests, and identifies itself as a student research crawler. It saves each page's visible text with its URL, fetch time and SHA-256 hash (`sources_manifest.json`). Every vocabulary item carries a quote, and `python scripts/fetch_kq_public_data.py verify` checks that each quote still appears in its snapshot (`provenance_report.md`). The sources, and what was deliberately not collected (the Pride Centre site, which disallows crawling; alumni registration; pages about named staff), are listed in `ml-service/data/kq_public/SOURCES.md`.

The Pride Centre programme names come from a third-party directory and should be checked against the official site (#21).

## Where full and real data lives

| Data | Where | In git? |
|---|---|---|
| All synthetic and public data above | This repository | Yes (small text files) |
| Development database | In memory, rebuilt on each start | – |
| Production database (real members) | MongoDB Atlas, once deployed (#34) | Never |
| Completed expert or participant rating sheets | `ml-service/ratings/real/` on the researcher's machine | Never (gitignored; delete at the end of the project as the consent form promises) |
| Any real profile exports | `data/real/` or `ml-service/data/real/` on the researcher's machine | Never (gitignored) |
| Trained artefacts (`*.pkl`, `*.joblib`, `*.onnx`, …) | Not needed: the recommender fits in seconds from the data | Never (gitignored) |

See also [data/README.md](../data/README.md) for the rules on adding data.

## Real-world validation (planned)

The blind expert rating study (#30) uses the rating kit: raters score mentor–mentee pairs 0/1/2 without knowing which system proposed them; `scripts/score_expert_ratings.py` computes agreement and ranking metrics. Until it runs, no claim is made about match quality for real people.
