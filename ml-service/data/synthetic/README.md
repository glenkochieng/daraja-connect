# Synthetic dataset

Generated by `python scripts/generate_synthetic_data.py` (seed 42): 160 mentors and 300 mentees.

> **Simulated data.** Nobody in these files exists. The relevance labels follow a formula
> the author chose, so results on this data test the pipeline and compare methods under
> those assumptions; they do not show that recommendations suit real people.

| File | Contents | Seen by the recommender? |
|---|---|---|
| `mentors.json` / `.csv` | Observable mentor profiles (current and former Kenya Airways staff) | Yes |
| `mentees.json` / `.csv` | Observable mentee profiles (Pride Centre alumni) | Yes |
| `splits.json` | Mentee ids for the validation (40%) and test (60%) splits | – |
| `hidden/mentor_latent.json` | True domain(s), expertise level (1–3) per topic, years | **No** |
| `hidden/mentee_latent.json` | Programme, target domain, career switch flag, true needs with importance | **No** |
| `hidden/simulated_relevance.csv` | Every mentee–mentor pair: coverage, domain fit, seniority fit, utility, grade (0/1/2) | **No** (evaluation only) |
| `hidden/generation_metadata.json` | Generator settings, label distribution, missingness counts | – |

## How profiles and labels are produced

1. **Latent attributes**
   * Mentors get a primary (and sometimes secondary) domain, 2–5 topics with a true expertise level, fleet experience and years of service.
   * Mentees get a Pride Centre programme (from the KQ public vocabulary), a target domain (25% switch domains), 2–5 needs with importance weights, and years of experience.
2. **Observable profiles** are written from the latent attributes, with noise:
   * Text comes from sentence templates and paraphrases; lower-level expertise is mentioned less often.
   * Mentees under-tag their needs; mentors over-claim level-1 topics or occasionally a topic they don't have.
   * Some tags, texts and specialisations are missing, and a few profiles have filler sentences.
   * Some mentors are unavailable, at capacity, or haven't given consent.
3. **Simulated labels** use only the latent attributes:

   ```
   coverage      = Σ_need importance × quality(mentor level)  /  Σ importance     quality: 1→0.25, 2→0.70, 3→1.00
   domain_fit    = 1 (same primary domain), 0.5 (mentor's secondary domain), else 0
   seniority_fit = clip((mentor_years − mentee_years − 1) / 6, 0, 1)
   utility       = 0.65·coverage + 0.20·domain_fit + 0.15·seniority_fit + N(0, 0.04)
   grade         = 2 if utility ≥ 0.62, 1 if utility ≥ 0.40, else 0
   ```

   The thresholds were fixed from the label distribution before any system was evaluated.
   On average each mentee has about 9 highly relevant (grade 2) and 18 at least somewhat relevant mentors among all 160 mentors.

## Known simplifications

* Text comes from a finite phrase bank, so mentors and mentees often share wording; this makes text matching easier than in real life. `scripts/run_sensitivity.py` tests a vocabulary-mismatch scenario.
* The utility formula is an assumption, not a validated model of good mentorship.
